# Automated Testing

This documentation explains how to unit test the CreatePlanValidator class using xUnit and FluentValidation.TestHelper

## Create Test Project

**Test Framework:** xUnit v2

**Assertion Library:** FluentAssertions (optional, but used for readable assertions)

**Validation Test Helper:** FluentValidation.TestHelper

**Folder Structure:**

```yaml
PlanService.Application.Tests
 └── Plans
     └── Commands
         └── CreatePlan
             └── CreatePlanValidatorTests.cs
```

STEP: 

Click the Method we want to test and create a unit test

Choose xUnit and it will automatically installed test project and the xUnit in our test project

Then, we install fluentassertion in our test project

#### ✅ Test Case 1 — Valid Command
```csharp
[Fact]
public void Validator_ForValidCommand_ShouldNotHaveValidationError()
{
    // arrange
    var command = new CreatePlanCommand()
    {
        Name = "TestPlan",
        Description = "TestPlan using Xunit",
        ContributionAmount = 100,
        CoverageAmount = 150,
        MinEntryAge = 20,
        MaxEntryAge = 30,
    };
    
    var validator = new CreatePlanValidator();
    
    // act
    var result = validator.TestValidate(command);
    
    // assert
    result.ShouldNotHaveAnyValidationErrors();
}
```

Explanation:
- Purpose: Ensure that a fully valid command passes all validation rules.
- Arrange: Create a valid CreatePlanCommand.
- Act: Call TestValidate to execute the validator.
- Assert: ShouldNotHaveAnyValidationErrors ensures no validation errors exist.

#### ✅ Test Case 2 — Invalid Command

```csharp
[Fact]
public void Validator_ForInValidCommand_ShouldHaveValidationError()
{
    // arrange
    var command = new CreatePlanCommand()
    {
        Name = "Te",
        Description = "TestPlan using Xunit",
        ContributionAmount = -1,
        CoverageAmount = -4,
        MinEntryAge = 10,
        MaxEntryAge = 5,
    };
    
    var validator = new CreatePlanValidator();
    
    // act
    var result = validator.TestValidate(command);
    
    // assert
    result.ShouldHaveValidationErrorFor(x => x.Name);
    result.ShouldHaveValidationErrorFor(x => x.ContributionAmount);
    result.ShouldHaveValidationErrorFor(x => x.CoverageAmount);
    result.ShouldHaveValidationErrorFor(x => x.MinEntryAge);
    result.ShouldHaveValidationErrorFor(x => x.MaxEntryAge);
}
```
Explanation:
- Purpose: Ensure that invalid input triggers specific validation errors.
- Invalid Values Tested:
  - Name too short 
  - ContributionAmount negative 
  - CoverageAmount negative 
  - MinEntryAge below allowed 
  - MaxEntryAge below MinEntryAge
- Assert: Each property is checked individually using ShouldHaveValidationErrorFor.

#### ✅ Test Case 3 — Using [Theory] for Multiple Invalid Inputs
```csharp
[Theory]
[InlineData("A")]
[InlineData("AB")]
[InlineData("AC")]
[InlineData("ABCD")]
public void Validator_ForInvalidName_ShouldHaveValidationError(string name)
{
    var command = new CreatePlanCommand()
    {
        Name = name,
        Description = "TestPlan using Xunit",
        ContributionAmount = 100,
        CoverageAmount = 150,
        MinEntryAge = 20,
        MaxEntryAge = 30,
    };
    
    var validator = new CreatePlanValidator();
    var result = validator.TestValidate(command);
    result.ShouldHaveValidationErrorFor(x => x.Name);
}
```

Explanation:
- Purpose: Test multiple invalid inputs in one test method.
- InlineData: Each name value is treated as a separate test case by xUnit.
- Professional Tip: Only include inputs that are actually invalid; otherwise, the test may fail unexpectedly.
