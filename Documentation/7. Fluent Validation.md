# Fluent Validation
This documentation covers installation, setup, and usage of FluentValidation for the PlanService microservice using Clean Architecture + CQRS.

FluentValidation is applied at the Application layer, primarily for commands like CreatePlanCommand to ensure data correctness before hitting the database.

---

## Installation

Install FluentValidation in the `Application Module` via NuGet:
```shell
FluentValidation.AspNetCore 
```
---

## Creating Validator File

In `Application Module` create a new file

### File: Plans/Commands/CreatePlanValidator.cs

```csharp
namespace PlanService.Application.Plans.Commands;

public class CreatePlanValidator : AbstractValidator<CreatePlanCommand>
{
    public CreatePlanValidator()
    {
        RuleFor(x => x.Name).NotEmpty().Length(3, 100);
        RuleFor(x => x.Description).NotEmpty().MaximumLength(500);
        RuleFor(x => x.ContributionAmount).GreaterThan(0).WithMessage("ContributionAmount must be greater than 0");
        RuleFor(x => x.CoverageAmount).GreaterThan(0).WithMessage("CoverageAmount must be greater than 0");
        RuleFor(x => x.MinEntryAge).InclusiveBetween(18, 100);
        RuleFor(x => x.MaxEntryAge).InclusiveBetween(18, 100);
        
        // Max Age must be >= Min Age

        RuleFor(x => x)
            .Must(x => x.MaxEntryAge >= x.MinEntryAge)
            .WithMessage("MaxEntryAge must be greater than MinEntryAge");
        
        // Coverage must be greater than contribution
        
        RuleFor(x => x)
            .Must(x => x.CoverageAmount > x.ContributionAmount)
            .WithMessage("CoverageAmount must be greater than CoverageAmount");
        
    }
}
```
Explanation of RuleFor Statements

Property-Level Rules – validate individual fields:
- RuleFor(x => x.Name).NotEmpty().Length(3, 100);
Ensures the Name is provided and its length is between 3 and 100 characters.
- RuleFor(x => x.Description).NotEmpty().MaximumLength(500);
Description cannot be empty and has a maximum length of 500 characters.
- RuleFor(x => x.ContributionAmount).GreaterThan(0).WithMessage("ContributionAmount must be greater than 0");
Contribution must be a positive number; prevents zero or negative values.
- RuleFor(x => x.CoverageAmount).GreaterThan(0).WithMessage("CoverageAmount must be greater than 0");
Coverage must also be a positive number.
- RuleFor(x => x.MinEntryAge).InclusiveBetween(18, 100);
Minimum entry age must be within a realistic range.
- RuleFor(x => x.MaxEntryAge).InclusiveBetween(18, 100);
Maximum entry age must also be within a realistic range.

---

Object-Level / Cross-Field Rules – validate multiple fields together:

- RuleFor(x => x).Must(x => x.MaxEntryAge >= x.MinEntryAge).WithMessage("MaxEntryAge must be greater than or equal to MinEntryAge");
Ensures that MaxEntryAge is not less than MinEntryAge.
Uses the entire object because the rule depends on multiple fields.

- RuleFor(x => x).Must(x => x.CoverageAmount > x.ContributionAmount).WithMessage("CoverageAmount must be greater than ContributionAmount");
Ensures financial logic is consistent, i.e., coverage must be greater than contribution.

**Requires access to both ContributionAmount and CoverageAmount, so it uses RuleFor(x => x).**

## Configure ServiceCollectionExtensions.cs

In `Application Module`
### File: Extensions/ServiceCollectionExtensions.cs
```csharp
services.AddValidatorsFromAssembly(applicationAssembly)
            .AddFluentValidationAutoValidation();
```

Explanation:
- AddValidatorsFromAssembly(applicationAssembly)
  - Automatically registers all validators in the assembly.
- AddFluentValidationAutoValidation()
  - Enables automatic validation in the pipeline.
- Any invalid command will trigger 400 Bad Request before reaching the handler.
