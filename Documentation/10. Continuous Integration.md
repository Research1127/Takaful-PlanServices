# 1️⃣ Project Structure

The CI pipeline is configured inside the repository using the following structure:

```
PlanService/
│
├── .github/
│   └── workflows/
│       └── dotnet-ci.yml
│
├── PlanService/
├── PlanService.Application/
├── PlanService.Domain/
├── PlanService.Infrastructure/
├── PlanService.Application.Tests/
│
└── PlanService.sln
```

### Explanation

- `.github/` → Contains GitHub configuration.
- `workflows/` → Contains CI/CD workflow files.
- `dotnet-ci.yml` → Defines the CI pipeline.
- `PlanService.sln` → The solution file used by the CI process.
- `PlanService.Application.Tests` → Contains unit tests executed during CI.

# 3️⃣ CI Pipeline Configuration

Below is the full workflow configuration:

```yaml
name: .NET CI Pipeline

on:
  push:
  pull_request:
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v3

      - uses: actions/setup-dotnet@v3
        with:
          dotnet-version: '8.0.x'

      - name: Cache NuGet packages
        uses: actions/cache@v3
        with:
          path: ~/.nuget/packages
          key: ${{ runner.os }}-nuget-${{ hashFiles('**/PlanService.sln') }}

      - name: Restore packages
        run: dotnet restore PlanService.sln

      - name: Build solution
        run: |
          dotnet build PlanService.sln --configuration Release
          echo "✅ Build succeeded"

      - name: Run tests
        run: |
          dotnet test PlanService.sln --verbosity normal
          echo "✅ All tests passed"
```

# 6️⃣ Step-by-Step Execution Flow

## 🔹 Step 1 – Checkout Repository

```yaml
- uses: actions/checkout@v3
```

Downloads the repository code into the GitHub Actions runner.

Without this step, the workflow would not have access to the solution files.

---

## 🔹 Step 2 – Setup .NET SDK

```yaml
- uses: actions/setup-dotnet@v3
  with:
    dotnet-version: '8.0.x'
```

Installs the .NET 8 SDK in the runner environment.

Ensures the CI pipeline uses the same .NET version as the development environment.

---

## 🔹 Step 3 – Cache NuGet Packages

```yaml
- uses: actions/cache@v3
```

Caches downloaded NuGet packages located in:

```
~/.nuget/packages
```

Purpose:
- Speeds up future builds
- Reduces dependency download time
- Improves pipeline performance

---

## 🔹 Step 4 – Restore Dependencies

```bash
dotnet restore PlanService.sln
```

Downloads all NuGet dependencies defined in the solution’s `.csproj` files.

This step must run before building the solution.

---

## 🔹 Step 5 – Build Solution

```bash
dotnet build PlanService.sln --configuration Release
```

Compiles the entire solution in **Release mode**.

If there are compilation errors:
- The pipeline fails
- The pull request cannot be merged safely

---

## 🔹 Step 6 – Run Unit Tests

```bash
dotnet test PlanService.sln --verbosity normal
```

Executes all test projects within the solution.

If any test fails:
- The pipeline fails
- The change is considered unstable
